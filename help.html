LIBRARY USER GUIDE

Cataloging and publishing

The Bell Yung Score Library is a static site designed for GitHub Pages. Its published inventory is in data/catalog.json and its cover photos are in images/ and thumbs/. The website itself runs in any modern browser without a database server.

Important: Your browser edits are not public updates.

Changes made through Edit record, New record, Delete record, or Restore stay on this device, in this browser. To publish them, choose Export → Download catalog.json, then replace the repository file data/catalog.json on GitHub and commit the change. Once GitHub Pages deploys the new commit, everyone sees the updated records.

Publish the website for the first time

  1. Create a GitHub repository, for example bell-yung-score-archive.
  2. Upload the contents of the downloaded website ZIP to the root of that repository using GitHub Desktop/Git, or upload in at least two batches through GitHub’s browser interface (maximum 100 files at once). Make sure index.html, app.js, data/, images/, and thumbs/ are all in the repository root.
  3. On GitHub, open Settings → Pages, select Deploy from a branch, then choose the main branch and /(root) folder. Save.
  4. After deployment, open https://YOUR-USERNAME.github.io/bell-yung-score-archive/. If you instead use a repository called YOUR-USERNAME.github.io, your URL is https://YOUR-USERNAME.github.io/.

Edit and publish catalog records

  1. Find a record and click Edit record. Save its title, composer, edition, shelf location, condition, or notes.
  2. For a new score, click New record. The next permanent BY-ID is generated.
  3. Use Export → Download catalog.json to save your complete inventory.
  4. In the GitHub repository, open data/catalog.json, choose Edit file, replace the content with the downloaded file (or upload it to the data/ folder and replace the existing file), and commit. For a larger catalog, updating the file using Git on your computer is easier.
  5. Refresh the deployed website after GitHub Pages finishes publishing.

Use Export → Download CSV to work in Excel. Use Import JSON to restore or move a browser backup; this also does not publish anything until you commit the exported JSON to GitHub.

Delete or restore a record

  1. Open the score from the gallery. Click Delete record (available either in the details panel or while editing) and confirm the deletion.
  2. The record is immediately hidden from the gallery in your browser and moved to Trash. To undo, click Trash in the top bar and click Restore beside that record.
  3. To publish a deletion or restoration, select Export → Download catalog.json and commit the exported file to data/catalog.json on GitHub.

Deleted entries remain recoverable in the JSON file under deleted_records, while visible catalog entries live under records. The original cover image files remain in images/ and thumbs/. Reserved archive IDs are never assigned to new scores. Deletions will not affect the public site until the updated JSON is committed.

Music background and external references

Each active record includes a brief introductory note and one or more links to external articles, score databases, library collections, or publisher information. Open any record and look under Learn about this music. These references are provided for orientation; many scores are anthologies, and links marked Broader repertoire or About this edition should not be interpreted as the exact physical edition. Links open in a new browser tab.

To update a source, open the record → Edit record. Edit Short background for visitors or the External sources field. Enter each source on one line as Link label | https://example.com/article | work. The last field may be work, collection, edition, or composer. Save, then export catalog.json and commit it to GitHub to publish. New records can start with these fields empty.

Images and cover photos

Existing score photos ship with the repository. You can attach a new cover in the editor; it is compressed, stored temporarily in your browser, and embedded into exported JSON. This works for occasional additions. For a long-term library, commit images as separate WebP or JPEG files to images/, then enter a relative path such as images/new-cover.webp (and optionally thumbs/new-cover.webp) in the record.

Note: Browser storage may be erased by clearing site data or switching devices, and large embedded images may exhaust browser storage. Export JSON regularly, and treat the repository copy of data/catalog.json as your durable published source of truth. Public GitHub Pages sites are visible to anyone with the URL; consider privacy and permission before publishing cover photographs, inscriptions, or provenance notes.

Local preview

With Python installed, from the extracted folder run python -m http.server 8000 (or python3 -m http.server 8000) and visit http://localhost:8000/. Browsers may block reading data/catalog.json when you double-click index.html, so a local HTTP server is the reliable preview method.
